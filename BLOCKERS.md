# Blockers

Anything that could not be confirmed or run, what was tried, and what unblocks it.
Status values: **OPEN** (blocks a gate), **WORKAROUND** (labelled fallback in place), **RESOLVED**.

| # | Blocker | Status | What was tried | What unblocks it |
|---|---|---|---|---|
| B-01 | No Kora **test** secret key in this environment, so no live sandbox call can be made. | RESOLVED (local) · OPEN (cloud, see B-08) | The owner's test key was used on the owner's machine (6 Oct 2026): charges, payouts, CAC and balances all answered (recorded fixtures in `tests/fixtures/kora/recorded/`, `lib/kora/fixtures/recorded/`). | Keys live only in `.env` / the host's environment settings, never in the repo. |
| B-02 | Kora says the Bank Transfer API must be **enabled on the account by Kora support**. | RESOLVED | Real sandbox: `POST /charges/bank-transfer` for ₦1,000,000 → 200. Above ₦1,000,000 → 422 (per-account cap, see DECISIONS D-37). | n/a. Larger orders are paid in instalments. |
| B-03 | Identity sandbox access was unknown until a call was made with the test key. | RESOLVED | Real sandbox: CAC works with the **numeric** id (`00000011`, `registration_type: RC`). The basic bank list is empty in sandbox (DECISIONS D-38). | `SIMULATE_IDENTITY` stays available (labelled) for environments without identity access. |
| B-04 | Kora must reach a public HTTPS URL for webhooks. | OPEN | n/a | Owner signs up at ngrok.com, claims a free static domain, and runs `ngrok config add-authtoken <token>`. `KORA_WEBHOOK_URL=https://<domain>/api/webhooks/kora` goes in `.env`, and the same URL is pasted into Kora dashboard → Settings → API Configuration. Until then, the reconciliation poller and the Re-check button resolve every order. |
| B-05 | No AI key. | WORKAROUND | Owner has no paid key. The AI client is OpenAI-compatible, so any free provider works by setting `AI_BASE_URL` / `AI_MODEL` / `AI_API_KEY`. | Free key from Google AI Studio (Gemini) or Groq. Without one, every parse shows `parsedBy = FALLBACK` in the UI. The deterministic fallback passes the golden tests on its own. |
| B-07 | Kora does not document the error body for an **invalid** CAC lookup (RC11111111). | RESOLVED | Real sandbox: 404 "CAC data not found", recorded in `lib/kora/fixtures/recorded/cac-RC11111111.json`; the client maps it to `KoraNotFoundError`. | n/a |
| B-06 | Webhook signature gate asks for "a real captured payload". Capturing one needs B-01 and B-04. | OPEN | Signature code is tested against Kora's documented payload shapes, a tampered copy, and number-format re-serialisation cases. | After B-01 and B-04, every received webhook is persisted raw, and `npm run capture:webhook-fixture` copies the latest real one into `tests/fixtures/kora/captured-webhook.json`. The test then runs against it. |
| B-08 | The Claude Code **cloud** container can't reach Kora: its network egress allowlist answers `403 Host not in allowlist: api.korapay.com`. So `npm run preflight` and `npm run test:sandbox` can't run there. | OPEN (cloud only) | Ran `npm run preflight` in the cloud session (6 Oct 2026): every row was the proxy's 403, not Kora. Preflight now ignores non-Kora answers, so they can't overwrite recorded fixtures. | Add `api.korapay.com` to the cloud environment's network allowlist, or run preflight locally / on the deployed host. Unit and integration tests need no network (Kora test double). |
