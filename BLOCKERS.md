# Blockers

Anything that could not be confirmed or run, what was tried, and what unblocks it.
Status values: **OPEN** (blocks a gate), **WORKAROUND** (labelled fallback in place), **RESOLVED**.

| # | Blocker | Status | What was tried | What unblocks it |
|---|---|---|---|---|
| B-01 | No Kora **test** secret key in this environment, so no live sandbox call can be made. P1 (preflight) and P4 (headless sandbox flow) gates need one. | OPEN | Checked process and user env vars for `KORA_*`. Did not take keys from other projects on this machine. | Owner pastes `KORA_SECRET_KEY=sk_test_…` and `KORA_PUBLIC_KEY=pk_test_…` into `.env`, then runs `npm run preflight` and `npm run test:sandbox`. |
| B-02 | Kora says the Bank Transfer API must be **enabled on the account by Kora support** ("Contact our team at support@korapay.com to request the activation of bank transfer payments via API", bank-transfers.md). Unknown whether that applies in test mode. | OPEN until preflight | Read bank-transfers.md. | Preflight row `bank-transfer charge`. If it returns an access error, email support@korapay.com and meanwhile use `ENABLE_CHECKOUT_REDIRECT=true` (Checkout Redirect, `POST /charges/initialize`, no activation needed). |
| B-03 | Identity sandbox access is unknown until a call is made with the test key. | OPEN until preflight | testing-identity-on-sandbox.md says test mode + test secret key + test data only. | If preflight shows `KoraAccessError` on CAC or bank-account-basic, set `SIMULATE_IDENTITY=true`. The same code path then runs against recorded fixtures, with a visible "SIMULATED IDENTITY" badge in the UI and on the record. |
| B-04 | Kora must reach a public HTTPS URL for webhooks. | OPEN | n/a | Owner signs up at ngrok.com, claims a free static domain, and runs `ngrok config add-authtoken <token>`. `KORA_WEBHOOK_URL=https://<domain>/api/webhooks/kora` goes in `.env`, and the same URL is pasted into Kora dashboard → Settings → API Configuration. Until then, the reconciliation poller and the Re-check button resolve every order. |
| B-05 | No AI key. | WORKAROUND | Owner has no paid key. The AI client is OpenAI-compatible, so any free provider works by setting `AI_BASE_URL` / `AI_MODEL` / `AI_API_KEY`. | Free key from Google AI Studio (Gemini) or Groq. Without one, every parse shows `parsedBy = FALLBACK` in the UI. The deterministic fallback passes the golden tests on its own. |
| B-07 | Kora does not document the error body for an **invalid** CAC lookup (RC11111111) or an unresolvable account. | WORKAROUND | Read the CAC and bank-account guides and the Postman examples: only success bodies are shown. | Preflight records the real error body to `lib/kora/fixtures/recorded/cac-RC11111111.json`. `SIMULATE_IDENTITY` then replays it; until then, the simulation returns a not-found body that says it is simulated. The client already maps any 4xx/`status:false` to a typed error, so the real shape needs no code change. |
| B-06 | Webhook signature gate asks for "a real captured payload". Capturing one needs B-01 and B-04. | OPEN | Signature code is tested against Kora's documented payload shapes, a tampered copy, and number-format re-serialisation cases. | After B-01 and B-04, every received webhook is persisted raw, and `npm run capture:webhook-fixture` copies the latest real one into `tests/fixtures/kora/captured-webhook.json`. The test then runs against it. |
